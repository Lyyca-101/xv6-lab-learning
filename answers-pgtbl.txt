1.Which other xv6 system call(s) could be made faster using this shared page? Explain how.
If xv6 has a syscall called getppid(which get the parent process pid),then it can be speeded up using
this shared page.
On the book,we can find the syscalls fstat and stat,when we once use one of these two
syscalls,the stat struct of the file can be cached in the shared page,next time we retrive
the stat struct,there is no need to get the stat by syscall and trapped in kernel mode again.
But in a multi-processed scenario,the file might be modified by another process,so there will
be some cache-consistency problem to be fixed.We need to flush the out-of-date state cache in 
the shared page,and use syscall to get the up-to-date stat.
